# 第一阶段当前实现

## 地图策略

- 当前联调地图：`supermarket_test_09`
- 正式比赛地图：`supermarket_test_030`
- 流程代码不绑定地图坐标。迁移时只替换地图任务点和逐面精调标定。
- 每个可用货架面只设置一个稳定锚点。到达并精调后，机器人保持观察姿态，沿货架横移到商品相机点。
- 不再采用每个货架面四个 Nav2 覆盖点的旧方案。

## 起点语义

- `START`：围栏前物理起点，不向 Nav2 下发。
- `PRE_START`：任务结束时使用的回程导航等待点，不作为起步直行动作的绝对终点。
- 启动定位导航并完成初定位后，第一阶段状态机按初始车头方向和 `/odom` 相对前进约 0.30m，先脱离后方围栏及其膨胀区。
- 机器人在物理 `START` 附近的实际摆放存在误差，因此清障完成位置由实时定位确定，不要求与 `PRE_START` 坐标重合，也不会先导航到 `PRE_START`。
- 清障命令经过 `velocity_smoother`、`collision_monitor` 和定位速度安全门；停稳且 Nav2 再次稳定后，直接从实际位姿导航到交付台。
- 完成全部商品后导航回 `PRE_START`，再通过直线退避 Action 返回物理 `START`。

## 购物票接口

控制台到达并精对齐交付台后发送正式 Action：

```text
/read_delivery_order  openarmx_task_msgs/action/ReadOrder
```

请求固定要求两个不同 SKU，识别节点返回结构化 `OrderLine[]`。识别节点内部执行：

```text
记录当前头部姿态
  -> 保持 Yaw，以 0.5rad/s @ 20Hz 插值 Pitch 到 -70deg
  -> 等待低头到位后的 1280x720 新彩色帧
  -> 调用 /openflex_grasp/query_vlm 复用常驻 Qwen
  -> 恢复识别前 Pitch
  -> 按 shelf_inventory.db 白名单校验 SKU 和数量
  -> 返回 ReadOrder.Result.lines
```

Qwen 内部原始输出使用以下 JSON，但 GUI 不再解析临时 String 话题：

```json
{
  "items": [
    {"sku": "杯子", "quantity": 1},
    {"sku": "舒克牙膏海盐薄荷", "quantity": 1}
  ]
}
```

约束：必须为两个不同 SKU，数量为 1 到 9，SKU 必须同时存在于只读商品目录和当前场景。Qwen 推理不设置固定 5 秒截止时间；明确失败或用户取消时停止流程，不自动使用旧的手动订单。操作员仍可在启动前主动从两个商品下拉框选择手动联调订单，此模式不会发起自动购物票识别。

## 完整顺序

1. 在物理 `START` 附近启动定位导航，等待初定位和 Nav2 全部内部服务稳定。
2. 按初始车头方向相对直行约 0.30m；该步骤只负责清障，不假定到达 `PRE_START`。
3. 停稳后从实时定位位置导航到交付台；购物票观察阶段使用 0.20m 净距精对齐，发送 `ReadOrder`，执行低头、取帧、共享 Qwen 推理、恢复和订单校验，确认成功后才退避。商品放置阶段仍使用任务点配置的 0.05m 净距。
4. 按订单队列导航到商品所在货架面锚点，精调并横移到商品。
5. 抓取、回 move、从商品点退避 0.30m，导航到交付台放置并退避。
6. 还有商品时从交付台退避位置直接开始下一件。
7. 全部完成后导航回 `PRE_START`，再直线返回物理 `START`。
